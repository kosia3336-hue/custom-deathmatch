## 1. 숨겨야 할 카드가 클라이언트로 넘어가는 문제

관련 코드: `server/src/socket/games/indian-poker/projection.ts`, `server/src/socket/utils.ts`, `lib/maskGameRecord.ts`

### 상황

인디언 홀덤은 상대 카드만 보이고 자기 카드는 못 보는 게임입니다. 방 상태를 모든 참가자에게 똑같이 보내면, 화면에서는 가려도 개발자 도구를 열면 자기 카드가 보입니다.

### 해결

서버는 실제 상태를 하나만 들고 있고, 클라이언트에 보낼 때마다 받는 사람이 봐도 되는 값만 골라 새로 만듭니다. 플레이어 두 명과 관전자가 받는 데이터가 모두 다릅니다. 랭크전에서 상대 닉네임을 가리는 것, 익명 물약을 쓴 사람의 이름을 가리는 것도 같은 방식으로 소켓마다 따로 만들어 보냅니다.

### 놓친 곳

판이 끝난 뒤 저장하는 기보는 이 처리를 거치지 않았습니다. 그래서 기록 화면을 열면 익명 물약을 쓴 사람의 실제 닉네임이 그대로 보였습니다.

기보 안에서 플레이어는 방 안에서만 쓰는 토큰으로 기록되어 있어서, 회원 ID로 찾아 가릴 수가 없었습니다. 그래서 기록을 조회할 때 기보 전체를 훑으면서 가려야 할 닉네임 문자열을 바꿔치기하는 방식으로 고쳤습니다. 원본은 그대로 저장하고, 보여 줄 때만 가립니다.

## 2. 운영 중인 길드를 건드리지 않고 새로 만들기

관련 코드: `db/guild_v4.sql`, `lib/guild-v4/`, `components/guild-v4/`

### 상황

길드 기능을 거의 새로 만들어야 했습니다. 그런데 이미 실제 회원이 가입한 길드 3개가 운영 중이었습니다. 기존 테이블이나 함수를 고치다가 실수하면 그 길드들의 데이터가 망가집니다.

### 해결

작업 전에 규칙부터 정했습니다.

- 기존 길드 테이블은 ALTER 하지 않습니다.
- 기존 길드 RPC 16개는 고치지 않습니다.
- 기존 길드 코드 폴더도 수정하지 않습니다.

새 기능은 새 테이블과 새 RPC로만 붙였습니다. 패치 12개에 걸쳐 테이블 13개와 RPC 26개를 추가했습니다. 화면은 로컬 전용 `/dev/guild`에서 가짜 데이터로 먼저 끝까지 만든 다음 운영에 연결했습니다. 길드 공지, 투자 장부, 랭크 카드, 길드 순위 정산이 이렇게 들어갔습니다.

개편하면서 기존 길드원 구성과 포인트는 한 번 초기화했습니다. 이 작업은 별도 패치(`db/guild_v4_reset.sql`)로 분리했고, 범위를 미리 정해 두었습니다. 길드는 해체하지 않고 이름도 유지합니다. 길드장만 남기고, 포인트는 초기화한 뒤 보상 포인트를 지급했습니다.

## 3. Supabase 무료 한도 초과로 서비스가 멈춘 일

관련 코드: `lib/auth/verifiedUser.ts`, `middleware.ts`, `app/api/rule-image/route.ts`, `app/api/notices/[noticeId]/body/route.ts`

### 상황

2026년 10월 24일, Supabase 무료 플랜의 전송량 한도를 넘겨 서비스가 멈췄습니다. 사용자 수에 비해 전송량이 지나치게 많았습니다.

### 원인

전송량이 새는 곳이 세 군데 있었습니다.

- 페이지를 열 때마다 로그인 확인(`auth.getUser`)을 두 번씩 했고, 미들웨어는 페이지를 옮길 때마다 회원 상태를 DB에서 다시 읽었습니다.
- 우편함 목록을 불러올 때 공지 편지의 본문 전체를 같이 받아 왔습니다.
- 게임 규칙 이미지를 볼 때마다 Supabase Storage에서 새로 받았습니다.

### 해결

- 로그인 확인은 토큰 서명만 검사하는 `getClaims`로 바꾸고, 같은 토큰은 1분 동안 결과를 기억합니다. 미들웨어의 회원 상태 조회도 1분 동안 기억합니다.
- 우편함 목록에는 공지 본문을 앞 300자만 저장해 두고, 편지를 열 때 본문을 따로 불러옵니다.
- 규칙 이미지는 우리 서버가 처음 한 번만 받아 디스크에 저장해 두고, 브라우저에는 1년 캐시를 걸었습니다. 이미지를 올릴 때마다 파일 이름이 새로 생기기 때문에 오래 캐시해도 문제가 없습니다.

로그인 확인을 1분 동안 기억하는 동작은 나중에 실수로 깨지지 않도록 테스트로 고정해 두었습니다 (`server/src/__tests__/web.supabase-egress.test.ts`).
